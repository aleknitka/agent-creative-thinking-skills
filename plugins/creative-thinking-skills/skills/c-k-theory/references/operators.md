# The Four C-K Operators — C→C, C→K, K→C, K→K

## C→C — Disjunction / partition

Add a property to a concept. Record whether the partition is restrictive or expansive.

Prompt: "What property, added to this concept, would have no precedent in our current knowledge?"

## C→K — Conjunctions attempted

Try to decide the concept from K. If K suffices, the concept becomes knowledge; if not, record the disjunction — what K pocket is missing.

Prompt: "What would make this concept decidable — what do we need to know?"

## K→C — Disjunction via knowledge

Use a K pocket to suggest a new concept or partition. This is where activated knowledge re-enters C.

Prompt: "Now that we know X, what new concept can we consider that we could not before?"

## K→K — Deductive expansion

Expand K itself — learn, test, or import knowledge. This operator grows the knowledge base that future concepts can build on.

Prompt: "What must we learn, and how will we learn it, to make this decidable?"

## Workflow

A typical expansion cycle is C→C (partition) → C→K (disjunction) → K→K (learn) → K→C (re-partition). Record each operation in the design square so generativity is visible.

## Keeping C and K distinct

Never put speculation in K; never decide a concept from another concept. The discipline is the value — it prevents both unconstrained ideation and premature analysis.
