# Forcing and Transfer — Making Constraints Productive

## Generating under a constraint

- Restate the constraint as the brief: "Solve [goal] without [blocked resource]."
- Produce 3–5 concepts per constraint that would still achieve the goal. No cross-constraint judging.
- Each concept must name a mechanism and an actor; a reworded baseline is not forced.

## Extracting the mechanism

For each concept ask:

- What makes it work *because* of the constraint, not despite it?
- Name the forcing insight in one sentence.
- Example: "No interface → pre-configured entry, where invite carries intent so first open shows real work, not a tour."

## Transfer test

Lift the constraint and keep what is valuable:

- Which mechanisms survive without the forcing?
- Where does the insight apply even when the constraint is gone?
- State the boundary where the transfer fails.
