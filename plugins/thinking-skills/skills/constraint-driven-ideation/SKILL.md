# Constraint-Driven Ideation

Remove what you take for granted and see what the problem forces you to invent. A well-chosen constraint kills the obvious answer so a better one has room.

The failure mode it prevents is open-ended brainstorming that converges on the same generic design every team would suggest.

## When to use

- The brief is open ("improve onboarding") and ideas feel interchangeable.
- The team keeps proposing the same category of answer (add a screen, add an email, add a meeting).
- You want new approaches that survive when the constraint is lifted — the insight outlives the limitation.

If unsure this is the right method, start with [thinking-router](../thinking-router/SKILL.md) — or see [references/when-not-to-use.md](references/when-not-to-use.md).

## When NOT to use (brief)

- You have a concrete baseline to improve → `scamper`.
- You need many ideas at once without a forcing frame → `divergent-thinking`.
- Facts are missing → research first.

## Process

1. **Intake — reuse before you ask.** State the problem, goal, hard limits that already exist, and what "generic" looks like today. Mark fact / assumption / speculation; ask only for gaps. See [references/constraints.md](references/constraints.md).

2. **Choose 2–3 forcing constraints.** Pick deliberately tight ones that block the generic answer: no interface, no budget, one day, offline-only, solo-only, no new code, 10× cheaper, must work for the most constrained user. See [references/constraints.md](references/constraints.md) and [scripts/constrain.py](scripts/constrain.py).

3. **Generate under each constraint.** For each, produce 3–5 concepts that would still achieve the goal. No judging across constraints during generation; each constraint is its own brief.

4. **Extract the mechanism.** For each concept ask: what makes it work *because* of the constraint? Name the forcing insight — that is what may transfer back.

5. **Lift and test transfer.** Remove the constraint and keep what is valuable: which mechanisms survive without the forcing? Select 2–3 transferable ideas with one probe each. See [references/examples.md](references/examples.md).

6. **Hand off.** Harden with `premortem`, vary with `scamper`, or systematize with `morphological-analysis` as needed.

## Rules

- Constraints are forcing, not realistic — keep them tight enough to block the generic.
- One constraint at a time; never hedge by softening two.
- Every concept must change the mechanism, not just rephrase the baseline under a new label.
- Label fact / assumption / speculation; state what would falsify the transfer.
- Honest provenance: call adaptations adaptations. See [references/provenance.md](references/provenance.md).
