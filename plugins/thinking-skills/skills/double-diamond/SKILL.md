# Double Diamond

Discover → Define → Develop → Deliver. Two diamonds: one for the problem, one for the solution. Diverge honestly in each diamond; converge decisively before opening the next.

The failure mode it prevents is solving the wrong problem well and picking a solution before either is understood.

## When to use

- Work needs both problem discovery and solution exploration.
- Scope is broad and must be narrowed twice — once on the problem, once on the solution.
- You want a scaffold that sequences other methods coherently.

If unsure this is the right method, start with [thinking-router](../thinking-router/SKILL.md) — or see [references/when-not-to-use.md](references/when-not-to-use.md).

## When NOT to use (brief)

- Problem is already well-defined → start in the second diamond.
- You need one quick idea → `crazy-eights` or `scamper`.
- Facts are missing → research first.

## Process

1. **Discover — diverge on the problem.** Map who is affected, what they do, where it hurts, and what is assumed. Use `question-storming`, `abstraction-laddering`, or `challenge-assumptions` inside this diamond. See [references/phases.md](references/phases.md).

2. **Define — converge on the problem.** Synthesize findings into one problem definition, one primary user, one measurable outcome, and the scope that is out. The definition is a bet, stated observably.

3. **Develop — diverge on solutions.** Generate candidate directions using `scamper`, `lateral-thinking`, `analogical-thinking`, or `morphological-analysis` within this diamond.

4. **Deliver — converge on the solution.** Select 2–3 candidates, harden with `premortem` or `futures-wheel`, and run validation probes. See [references/methods.md](references/methods.md).

5. **Plan validation.** For each candidate, define success signal, measurement method, and decision rule. Keep the plan small enough to run this month.

6. **Hand off.** Report the problem definition, candidates, and validation plan as one artifact; name what remains speculative. See [references/examples.md](references/examples.md).

## Rules

- Two diamonds — do not skip the first; a strong second diamond on the wrong problem is waste.
- Diverge before converging in each diamond; converging too early in either reproduces the starting bias.
- State the problem definition observably; a vague definition cannot be validated.
- Keep the validation plan small — one probe per candidate where possible.
- Label fact / assumption / speculation.
- Honest provenance: call adaptations adaptations. See [references/provenance.md](references/provenance.md).
