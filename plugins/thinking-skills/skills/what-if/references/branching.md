# Branching — One Mutation, One World

A what-if world is a controlled thought experiment, not a brainstorm. Change one thing, hold the rest fixed, and see what the change forces.

## The one-at-a-time rule

1. **State the mutation in one sentence.** Format: *"What if [assumption] were [mutated value]?"*
2. **Freeze the rest.** Write down the assumptions you are keeping: same users, same budget, same laws, same time horizon. This makes the causal attribution possible.
3. **Change only the target.** If the world needs a second change to be interesting, note it as a *derived* consequence, not a second premise.
4. **Do not rescue reality.** "That would never happen" is out of scope inside the world. Record the objection in a separate column if it helps.
5. **Timebox.** 10–15 minutes per world; 3–5 worlds per session. Depth beats a list of premises.

Combinatorial passes are allowed only after each mutation has its own sketch. Then combine two premises and label the result as a *combined world* — it is harder to attribute causality, but useful for stress-testing interactions.

## World sketch template

Use this in step 3. Keep each field to 1–3 bullets.

```
Mutation: What if <assumption> were <mutated value>?
Type: resource | interface | actor | rule | scale | time
Held fixed: <3–5 assumptions you are not changing>

Premise: <one sentence describing the world>

What changes immediately:
- ...

What stays the same:
- ...

What must be true for this world to hold:
- <physical, economic, social, or technical precondition>

Who thrives / who loses:
- Thrives: ...
- Loses: ...

New frictions:
- <what gets harder, riskier, or more contested>

Artifact:
- <what would exist in this world that does not exist now>

Open questions:
- ...
```

## Field guidance

**Premise** — one sentence, no hedging. "In this world, expert documentation time is unlimited." Avoid "we could perhaps imagine a future where..."

**What changes immediately** — direct consequences of the premise, before anyone adapts. Keep them mechanical.

**What stays the same** — this is the control group. It prevents the common error of changing everything at once.

**What must be true** — the preconditions. If the world requires a technology, norm, or institution that does not exist, say so. This is where the world becomes informative rather than magical.

**Who thrives / who loses** — distributional effects. New worlds create winners and losers; ignoring this produces naive transfer insights.

**New frictions** — every world has new problems. If yours has none, the mutation was too small or the sketch is too shallow. Name at least two.

**Artifact** — make the world concrete: a product, a ritual, a contract, an interface, a role. Abstract worlds do not transfer.

**Open questions** — what you would need to know to take the world seriously. These become probes later.

## Anti-patterns

- **The disguised constraint.** "What if we had unlimited budget — but still had to use the same vendors and timeline?" That is not a mutation; it is the current world with more money.
- **The magic step.** "And then AI solves it." Name the mechanism. If the mechanism is unknown, label it speculation.
- **The second premise.** "What if there were no interface and users loved push notifications?" The second clause is a consequence you have assumed, not derived. Trace it instead.
- **The comfort world.** A mutation that leaves the current business model intact rarely produces a transferable insight.
- **The single sketch.** One world is an anecdote. Compare at least three mutations, ideally from different types.

## Worked mini-sketch

```
Mutation: What if expert time to write documentation were unlimited?
Type: resource
Held fixed: same employees, same tools, same budget for tooling, same customers

Premise: Documentation can be produced and refreshed as fast as work happens.

What changes immediately:
- Every question answered in a support thread can become a durable answer.
- Stale pages can be rewritten rather than patched.

What stays the same:
- Experts still dislike writing; incentives still matter.
- Readers still need to find the right page.

What must be true:
- Capture is cheap enough that writing does not compete with delivery work.
- Someone still owns structure and duplication control.

Who thrives / who loses:
- Thrives: new hires, support staff.
- Loses: people whose status comes from being the only source of an answer.

New frictions:
- Volume grows faster than quality control.
- Conflicting answers coexist without a resolution mechanism.

Artifact: a knowledge base that grows as a by-product of answering questions.

Open questions: what makes capture cheap? Who arbitrates contradictions?
```
