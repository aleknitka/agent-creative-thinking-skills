# When Not to Use Board-Game Abstraction

- Need to feel space and handoffs physically → `bodystorming` (bodies beat board).
- Need leverage/delays before any game → `causal-loop-diagram`.
- Need shared mess/worldviews first → `rich-picture-catwoe`.
- Need a validated simulation for decision → build a model; a playable abstraction is not a forecast.
- Group cannot spare 40 min → use `liberating-structures` / `dot-voting-prioritize` for quick convergence.
- The problem is already a game (incentive, competition) — abstracting again adds little; map it directly.
