# Worked Example — Rebuilding Onboarding from Fundamentals

## Goal

New accounts reach first meaningful value within 7 days.

## Candidate constraints

| Statement | Type | Evidence |
|---|---|---|
| First value needs a working data connection | Fundamental (capability) | Product cannot render without data |
| Data residency in EU | Regulation | Legal memo 2025-03 |
| Tutorial must be completed before value | Inherited | No team measured; one invite team skips it |
| Activation must use email | Inherited | No policy document; other channels exist |
| Value must be inside product on first open | Inherited | Boundary, not capability |

## Stripped problem

"Achieve first value within 7 days under: data connection available, EU residency, observed invite vs solo split."

## Three rebuilt approaches

1. **Pre-configured entry:** invite or import carries intent so first open shows real work, not a demo. Keeps no tutorial; drops email-only.
2. **Checklist on real data:** onboarding is a task-based checklist overlaid on actual work. Keeps inside-product but drops tutorial.
3. **Peer-propagated artifact:** a teammate's shared artifact is the entry and orientation. Keeps team path, drops solo-first assumption.

Each approach satisfies fundamentals; each drops a different inherited constraint and names the probe that would falsify the drop.
