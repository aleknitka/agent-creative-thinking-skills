# When NOT to Use Analogical Thinking

Analogical thinking is for **transferring a mechanism across domains**. Many adjacent methods generate ideas faster or fit the situation better.

## Quick triage

| Your situation | Better fit | Why |
|---|---|---|
| You need surprise, not transfer | Random stimulus / forced connections | Random pairing provokes; it does not require structural alignment or limits |
| You want to break the current frame sideways | Lateral thinking | Deliberate discontinuity; analogy preserves a structure you may need to abandon |
| You have a concrete baseline to improve | SCAMPER | Local operators on known components; analogy is overkill unless an Adapt prompt points outward |
| You want the best in-industry practice | Benchmarking | Near-domain copying is the honest name; it imports norms, not mechanisms |
| You doubt the current design's premises | First-principles thinking | Derive from fundamentals; analogy borrows someone else's assumptions |
| The problem is a recurring technical tradeoff | TRIZ contradiction thinking | TRIZ offers abstracted solution patterns for contradictions; analogy is unstructured |
| The problem is vague or the goal unclear | Question storming / framing work | Analogy will happily map a vague problem to a vague source |
| You already have candidates and need to choose | Premortem / options portfolio | Evaluation and hardening, not discovery |
| You need many concepts from several partial ideas | Concept blending | Blending synthesizes; analogy maps one source onto one target |

## Don't confuse

- **Analogical thinking vs. forced connections:** forced connections pair unrelated stimuli to loosen associations; the value is the provocation. Analogical thinking demands a relation-level mapping and a breakpoint analysis; the value is the mechanism. Using analogy language for random inspiration produces confident nonsense.
- **Analogical thinking vs. lateral thinking:** lateral thinking moves the frame, often by provocation. Analogical thinking keeps your problem frame and imports a mechanism into it. If the frame itself is wrong, analogy will make the wrong frame more elaborate.
- **Analogical thinking vs. SCAMPER:** SCAMPER's Adapt operator can point to another domain, but SCAMPER is a local variation sweep. Once the question becomes "how does that domain actually make this work?", switch.
- **Analogical thinking vs. benchmarking:** benchmarking compares within a reference class and copies practices. Cross-domain analogy deliberately leaves the reference class to find a different causal structure. Calling a competitor visit "analogical thinking" hides that you are importing the same assumptions.
- **Analogical thinking vs. first principles:** first principles asks what must be true from fundamentals. Analogy asks what worked elsewhere under similar relations. Use first principles to check whether the borrowed mechanism is physically or economically possible.
- **Analogical thinking vs. metaphor:** a metaphor illuminates; an analogy should support inference. If nothing follows from the comparison that you did not already know, it is a metaphor.

## Preconditions

Do not start unless:

1. The problem can be stated in 3–5 concrete sentences.
2. A structural abstraction exists (function, flow, constraint, feedback).
3. You can name at least two relations to match.
4. You can describe the source domain accurately enough to avoid inventing it.
5. You have room for a probe; adoption without testing is not this method.

## Handoff triggers

| When | Hand off to |
|---|---|
| The structural statement reveals a hidden assumption | Assumption challenging or first principles |
| You need many candidate mechanisms cheaply | Divergent thinking, then return to map the best two |
| A borrowed mechanism conflicts with an existing constraint | TRIZ contradiction thinking |
| You have a candidate concept and need to stress it | Premortem |
| You need to combine two partial mechanisms | Concept blending |
| The analogy keeps sliding into a metaphor | Stop; restate relations or switch to forced connections for provocation only |
| No far domain yields a credible mapping | Benchmark near practice and say so; do not manufacture depth |

## Anti-patterns

- Running analogy after the decision is already made, to justify it.
- Mapping ten domains shallowly instead of two deeply.
- Treating a famous cross-domain metaphor as evidence.
- Skipping the limits section because the mapping is exciting.
- Adopting a mechanism at full scale without a probe.
